# Absorb Archive materials into PageLM shared namespaces

Status: accepted.

Decision source: QAI Archivist ADR 0012 at commit `245e2373`.

The target is a full replacement of the Archive material surface if a bounded migration pilot succeeds. The replacement will not reproduce QAI Collection, Record, File, RagSource, admission, or revision domains; it absorbs only the material, access, provenance, and retrieval data required by PageLM's existing chat-centred product. Authentik identity and QAI person and organization data remain external corporate authorities after cutover.

PageLM is integrated as a separate learning application at `https://archive.qai.lge.com`, replacing the host's prior route after its exact owner and recovery boundary are verified. After cutover PageLM becomes the material, access-policy, retrieval, and evidence authority for migrated content. The fork uses its own Authentik OIDC client with a backend-managed opaque browser session, binds local state to the stable Authentik subject, and resolves that subject to a current active QAI person user on every REST and WebSocket request. Browser bearer credentials, forwarded identity headers, usernames, email addresses, integration users, QAI integration exceptions, and unclassified users cannot establish or transfer ownership.

The migration reads QAI through one narrow read-only adapter. Each current active Collection becomes one PageLM shared search namespace. Its `parent_id` exists only for the tree picker, and its effective user and organization subjects become flat namespace grants; PageLM has no runtime access inheritance engine. Each current active Record contributes only current admitted source assets and search rows, with former identities retained as provenance metadata rather than Library, Material, Record, RagSource, admission, or revision services.

Personal uploads retain PageLM's existing `chat:{id}` namespace and lifecycle. The UI labels authorized shared namespaces as 공유 자료실 and groups their Record-derived content as 학습 자료 without corresponding domain entities. A chat source bag stores the exact personal and shared namespace IDs selected for that chat; an empty bag performs no shared-material retrieval. A tree selection expands into the exact accessible namespace IDs at selection time, and future descendants are never silently included. Pilot shared namespaces are read-only snapshots.

PageLM's existing chat-centred learning workflow and per-user global Learning Bag remain intact. A chat-originated 학습 파생물 inherits its originating turn's namespace dependencies instead of running a separate search. PageLM rechecks current ownership and namespace access before later reads, downloads, or streams. Source replacement or deletion does not retroactively invalidate a derived artifact while namespace access remains. Citations open authenticated original assets inside PageLM; exact element navigation is deferred. A downloaded offline copy is an export outside later revocation control.

The pilot copies a bounded Archive snapshot into a PageLM-owned Milvus collection and private asset storage. Compatible dense vectors are reused only when the Gemini model, dimension, and embedding version match exactly. BM25 is rebuilt, and namespace and grant metadata are rewritten for PageLM. Search and asset reads then run without Archive content runtime calls. A successful later cutover freezes Archive writes, imports the final delta, validates the PageLM copy, and switches the route; there is no permanent synchronization worker or dual-write path.

The production retrieval path is direct Gemini query embedding plus Milvus dense-and-BM25 hybrid search behind the existing `rag.search` interface. It adds no query rewrite or LLM rerank during the pilot. JSON, Chroma, generic provider factories, public storage mounts, `quality_knowledge_search`, `/api/v2/qai/search`, and other QAI search endpoints are removed rather than retained as alternate paths.

PageLM uses one OpenAI-compatible LiteLLM generation boundary at `proxy.qai.lge.com`. Allowlisted model aliases may route operationally to approved Azure OpenAI or Vertex AI services without provider-specific clients or credentials in the fork. Search and upload indexing use Vertex AI `gemini-embedding-001` at 1536 dimensions directly. PageLM receives a dedicated bounded LiteLLM virtual key, and credentials remain runtime-injected. Replacing upstream TTS, transcription, or image-generation providers is outside the migration pilot.

The pilot uses one non-sensitive parent Collection and at most two children, covering organization and explicit user grants, nested selection, multiple Records and files, and preferably one DataSource. It requires 100% asset, search-row, and grant migration integrity; zero namespace, search-result, or asset authorization exposures; expected material in the top ten for at least 90% of fixed Korean, English, and identifier questions; all existing learning flows end to end; authenticated citations and downloads; zero Archive content runtime calls after snapshot; and verified clean redeploy and prior-route recovery.
